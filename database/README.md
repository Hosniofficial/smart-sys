# قاعدة البيانات

يحتوي هذا المجلد على migrations وملفات التشغيل الضرورية. الحزمة الموجودة في `database/production/` لقطة تاريخية مؤرخة `2026-10-12` وليست متوافقة أو معتمدة للنشر مع مصدر التطبيق الحالي.

## اللقطة التاريخية — غير معتمدة للاستيراد

- `production/smartsys_production_schema_20261012.sql` و`production/smartsys_production_core_seed_20261003.sql` — ملفات اللقطة التاريخية.
- `production/smartsys_production_export_manifest_20261012.json` — يحدد حالة الحزمة `stale_do_not_import`.

مصدر التطبيق يحتوي migrations حتى `031_revoke_sessions_after_password_change`، بينما تحقق التصدير القديم حتى `024` وكان seed يسجل `001–021`. لذلك لا تثبت مراجعة DDL أو restore السابقة توافق هذه اللقطة مع التطبيق الحالي. يرفض `database/import_railway_test_db.ps1` استيرادها حتى إنشاء حزمة جديدة واختبارها واعتمادها.

لإصدار حزمة جديدة، اتبع شروط [حزمة قاعدة البيانات التاريخية](production/README.md#شروط-إصدار-حزمة-بديلة)، ولا تنفذ migrations على قاعدة قائمة قبل مراجعة ledger ونسخة احتياطية قابلة للاستعادة.

لفحص سجل migrations في قاعدة Railway دون تغييرها، شغّل `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\database\audit_railway_migrations.ps1` من جذر المشروع. أدخل المضيف والمنفذ الخارجي واسم القاعدة ومستخدمًا مخصصًا بصلاحية قراءة فقط؛ كلمة المرور تدخل مخفية ولا تُحفظ في ملفات المشروع. الفاحص لا يشغّل migrations، ونتيجته لا تثبت وحدها تطابق المخطط أو الجاهزية الإنتاجية.

بعد أخذ snapshot/backup قابل للاستعادة، وللقاعدة المؤقتة الخالية من بيانات التشغيل فقط، شغّل `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\database\apply_railway_pending_migrations.ps1 -WhatIf` أولًا؛ هذا فحص preflight للقراءة فقط ويقبل حسابًا بصلاحية قراءة. إذا نجح وتأكدت من النسخة الاحتياطية والهدف، أعد تشغيل الأمر دون `-WhatIf` بحساب كتابة؛ يتحقق من الخادم `8.4.11`، ومن أن سجل القاعدة هو بالضبط `001–024`، وأن الجداول اللازمة موجودة وجداول التشغيل الأساسية فارغة، ثم يتطلب كتابة تأكيد صريح `MIGRATE railway 024-027` قبل تطبيق `025–027` عبر runner الرسمي. لا تستخدمه على قاعدة إنتاج أو قاعدة تحتوي بيانات عملاء.

## migrations

تحتوي `migrations/` على migrations المرقمة `001–032`. لا تحذفها أو تعِد ترقيمها؛ يعتمد عليها سجل التطبيق وإعادة بناء قواعد جديدة. تضيف `026` أساس أسعار الصرف ولقطات مبالغ العملات، وتضيف `027` حقول تدقيق عكس الرصيد الافتتاحي، وتفرض `029` تفرد أرقام المرتجعات داخل المستأجر بعد فحص التكرارات، وتمنح `030` صلاحيات مساهمات المالك لأدوار الإدارة العامة، وتضيف `031` إصدار جلسة المستخدم لإبطال رموز الوصول عند تغيير كلمة المرور أو تسجيل الخروج من جميع الأجهزة. تضيف `032` جداول أوامر صيانة أجهزة العملاء وقطع الغيار. تم التحقق من تشغيل migrations حتى `031` في قاعدة `.env` المحلية بعد أخذ نسخة احتياطية؛ migration `032` جديدة ولم تُشغّل بعد. افحص سجل القاعدة الفعلي وخذ نسخة احتياطية قبل تشغيلها. طبّق migrations المطلوبة حسب إصدار التطبيق وسجل القاعدة الفعلي، لا حسب اللقطة التاريخية.

بيانات التهيئة المطلوبة، ومنها خطة `promo_3months`، موجودة في ملف seed الإنتاجي التاريخي؛ لا توجد ملفات SQL إضافية أو نسخ احتياطية SQL داخل مجلد قاعدة البيانات.
