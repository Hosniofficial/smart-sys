# قاعدة البيانات

يحتوي هذا المجلد على سجل migrations وأدوات تشغيل قاعدة البيانات، بالإضافة إلى baseline للمخطط وبيانات تهيئة تطويرية.

## Baseline وبيانات التطوير

- `schema.sql` مخطط أساسي بعد تطبيق migrations من 001 إلى 051، ويتضمن سجل migrations لإظهارها كمطبقة. لا يحتوي بيانات التطبيق.
- `demo_seed.sql` يحتوي بيانات التهيئة العامة فقط: الوحدات والخطط والأدوار والصلاحيات وربطها وطرق الدفع وقواعد تحديد المعدل. لا يحتوي مستخدمين أو مستأجرين أو معاملات تشغيلية.
- أُنشئ الـbaseline في قاعدة MariaDB مؤقتة ومعزولة من حالة محلية عند migration 038، ثم طُبقت migrations 039–051 عبر المشغّل الرسمي. تم التحقق من استيراد الملفين وتشغيل `status`، لكن لم يُختبر الاستيراد على قاعدة Railway الإنتاجية.
- الملفان مخصصان لقواعد التطوير والاختبار الجديدة فقط، ولا يُستوردان إلى الإنتاج أو قاعدة قائمة.

لإنشاء قاعدة تطوير جديدة:

```powershell
mysql -u root -p -e "CREATE DATABASE smartsys_dev CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root -p smartsys_dev
```

ثم من موجه MySQL:

```sql
SOURCE C:\xampp\htdocs\SmartSys\database\schema.sql;
SOURCE C:\xampp\htdocs\SmartSys\database\demo_seed.sql;
```

بعدها يمكن التأكد من سجل التهيئة:

```powershell
$env:DB_DATABASE = "smartsys_dev"
php database/migrate.php status
```

يجب أن تظهر migrations من 001 إلى 051 كمطبقة. لا تشغّل `up` بعد استيراد الـbaseline؛ استخدم إما هذا الـbaseline أو التهيئة بالمشغّل على قاعدة فارغة، وليس الطريقتين معًا.

تظل الملفات الفردية في `migrations/` سجل التغيير التاريخي والمصدر المعتمد للتعديلات المستقبلية؛ لا تحذفها أو تعدّل migrations مطبقة. ملف `tests/Integration/Fixtures/mysql_schema.sql` مخطط تاريخي تستخدمه اختبارات migrations، وليس بديلًا عن `schema.sql`.

## migrations

تحتوي `migrations/` على migrations المرقمة. لا تحذفها أو تعِد ترقيمها؛ يعتمد عليها سجل التطبيق وإعادة بناء قواعد جديدة. افحص الحالة قبل التشغيل:

```powershell
php database/migrate.php status
```

لا تشغّل `up` إلا على قاعدة تطوير أو اختبار معزولة وبعد مراجعة migrations المعلقة. قبل أي تغيير على قاعدة قائمة، تحقق من سجلها وخذ نسخة احتياطية قابلة للاستعادة. لا تشغّل migrations على قاعدة استُعيد إليها dump كامل يحتوي سجلها.

تتطلب migrations المعلّمة `REQUIRES_BACKUP_CONFIRMATION` تأكيدًا صريحًا ومعرّف نسخة احتياطية:

```powershell
php database/migrate.php up --confirm-irreversible --backup-reference=REAL_RESTORABLE_BACKUP_ID
```

استبدل `REAL_RESTORABLE_BACKUP_ID` بمعرّف نسخة فعلية، ولا تستخدم الأمر قبل استعادة النسخة في بيئة اختبار والتحقق منها. يحتفظ سجل نشر الأوامر بمعرّف النسخة؛ الخيار يضيف حاجزًا تشغيليًا ولا ينشئ نسخة احتياطية بنفسه.

للاتصال بخادم بعيد عبر TLS، مرر إعدادات الهدف عبر متغيرات العملية `DB_*`، واضبط `DB_SSL_CA` إلى شهادة CA؛ يتحقق runner من شهادة الخادم افتراضيًا عند استخدام CA.

تحتوي migrations الأخيرة على تغييرات لأوامر صيانة الأجهزة، وصلاحيات الفروع والمستأجرين، وعروض الأسعار وحملات الأسعار. راجع ملفات migration نفسها لمعرفة تفاصيل كل تغيير.

Migration `040` تضيف علاقات مرجعية محددة، وتوحد أنواع بعض أعمدة الربط، وتزيل تعليقات الأعمدة من الجداول المحددة. وهي تحفظ السجلات التاريخية، ولا تفصل إلا المراجع اليتيمة المعروفة محليًا بعد التحقق من أرقام السجلات والمراجع المتوقعة.

Migration `041` تحذف أعمدة قديمة ثبت خلوها من البيانات وعدم استخدامها أو اعتماد أي فهرس/قيد/عرض/مشغل/إجراء مخزن/حدث مجدول عليها. تتوقف قبل أي حذف إذا وجدت بيانات أو اعتمادًا على أحد الأعمدة، وتتطلب تأكيد نسخة احتياطية قابلة للاستعادة عبر المشغّل.

Migration `042` تزيل آخر تعليق عمود مطلوب في `cash_vouchers`، وتوحّد أوصاف الصلاحيات المحددة إلى الإنجليزية مع إبقاء `display_name` بالعربية. تتحقق من القيم الحالية قبل التعديل.

Migration `043` تضيف العلاقات المرجعية الأربع المتبقية التي أمكن التحقق من دلالتها وسلامة بياناتها: فرع المورد، ومستأجر وحدات المنتجات وتفاصيل المبيعات، وقاعدة تحديد المعدل. توائم نوع `suppliers.branch_id` مع نوع مفتاح الفروع قبل إضافة العلاقة.

Migration `044` تحذف `products.is_active_product` المكرر فقط إذا تطابقت قيمه مع `products.active` ولم يوجد اعتماد غير متوقع عليه؛ وتزيل فهرسه المنفرد. كما توحّد تنبيهات انتهاء الصلاحية مع جدول `product_expiry` الذي تستخدمه عمليات الشراء والمرتجعات. تتطلب تأكيد النسخة الاحتياطية لأنها لا تعيد العمود عند rollback.

Migration `045` تحذف جداول `documents`, `payment_transactions`, `user_preferences`, و`account_device_associations` بعد رفض التنفيذ إذا احتوى أي منها بيانات، أو وجد مرجع أجنبي وارد، أو اعتماد في عرض/مشغل/إجراء/حدث مجدول. تتطلب تأكيد النسخة الاحتياطية لأنها غير قابلة للعكس. أزيل من وسيط الاشتراك فحص عدد الحسابات المرتبطة بالجهاز الذي لم يكن له أي مسار كتابة؛ وتبقى فحوص بصمة الجهاز ومخاطرها الأخرى.

Migration `049` تنشئ `branch_settings` لتخصيص إعدادات الطباعة والقوالب لكل فرع، مع إبقاء إعدادات المنشأة هي القيم الافتراضية وإمكانية حذف تخصيص الفرع للعودة إليها.

Migration `050` تحفظ طريقة تسعير الضريبة لكل فاتورة وعرض سعر، وتضيف قيمة الضريبة لكل بند مبيعات؛ الإعداد الافتراضي غير شامل للمحافظة على تفسير الفواتير القديمة.

Migration `051` توحّد فهرس token القديم إلى فهرس فريد ببادئة 255 حرفًا، وتضمن تحقق JSON في `notifications.data`. ترفض التنفيذ إذا وجدت بادئات token مكررة أو JSON غير صالح، وتتطلب نسخة احتياطية قابلة للاستعادة بسبب تغيير القيود والفهرس.

بيانات الإنتاج موجودة على Railway. لا تحفظ نسخًا تشغيلية أو بيانات اعتماد داخل المستودع؛ ملفا baseline وبيانات التطوير أعلاه مخصصان للتهيئة المحلية فقط.
